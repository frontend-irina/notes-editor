# Drag-and-drop блоков

## Назначение

Документ определяет целевое поведение перетаскивания блоков в надстройке над
Tiptap. Эталоном является стандартный drag-and-drop BlockNote.

Основные источники:

- [BlockNote — Side Menu](https://www.blocknotejs.org/docs/react/components/side-menu);
- [BlockNote — Manipulating Blocks](https://www.blocknotejs.org/docs/reference/editor/manipulating-content);
- [BlockNote — Document Structure](https://www.blocknotejs.org/docs/foundations/document-structure);
- [BlockNote — Vanilla JS](https://www.blocknotejs.org/docs/getting-started/vanilla-js).

Требования дополнительно сверены с исходным кодом установленной в проекте
версии `@blocknote/core@0.54.0`. Детали, помеченные как детали реализации, не
следует считать стабильным публичным API BlockNote.

Связанные спецификации:

- [Идентификатор блока](./block-id.md);
- [Formatting Toolbar](./toolbar.md);
- [Архитектура проекта](../architecture/project.md).

## Термины

- **drag handle** — кнопка с иконкой перетаскивания в боковом меню блока;
- **исходный блок** — блок, для которого пользователь начал drag;
- **перетаскиваемый диапазон** — один блок или несколько выбранных блоков;
- **drop position** — допустимая позиция вставки, показываемая drop cursor;
- **исходный редактор** и **целевой редактор** — экземпляры редактора, из
  которого и в который переносятся блоки.

## Единица перемещения

Блок перемещается как целая структурная единица:

- сохраняются его `type`, `props`, `content` и `id`;
- все `children` перемещаются вместе с родительским блоком;
- порядок нескольких перемещаемых блоков и их дочерних деревьев сохраняется;
- drag-and-drop не должен превращать блочное выделение в обычную вставку текста.

Формат ID не рассматривается в этой спецификации. Требуется только сохранять
ID при перемещении существующего блока и не создавать второй блок с тем же ID
в одном документе.

## Боковое меню и начало перетаскивания

В редактируемом редакторе при наведении на блок слева показывается Side Menu.
Стандартное меню содержит кнопку добавления блока и drag handle. Кнопка drag
handle имеет два разных действия:

- drag начинает перенос блока;
- обычный click открывает Drag Handle Menu с командами блока.

Требования к интерфейсу:

- область drag handle имеет нативный атрибут `draggable`;
- кнопка получает локализованное доступное имя;
- Side Menu привязан к блоку под указателем, включая вложенные блоки;
- открытие Drag Handle Menu фиксирует Side Menu у текущего блока, а закрытие
  снимает фиксацию;
- во время ввода с клавиатуры Side Menu скрывается;
- в read-only режиме Side Menu и возможность перемещения не показываются;
- в headless-режиме DOM-перетаскивание не запускается.

Стандартный Side Menu можно заменить собственным компонентом или отключить
через `sideMenu={false}`. Отключение стандартного UI не должно запрещать
структурные команды публичного API.

## Правило выбора перетаскиваемых блоков

При начале drag редактор определяет диапазон следующим образом:

1. Если исходный блок входит в текущее выделение нескольких блоков,
   перемещается весь выделенный диапазон.
2. Если исходный блок не входит в такое выделение, перемещается только он.
3. Обычное текстовое выделение внутри одного блока не превращает drag handle в
   перенос нескольких блоков.
4. Если выделение пересекает разные уровни вложенности, диапазон расширяется до
   целых внешних блоков, чтобы не оставить пустые структурные фрагменты.

Непосредственно перед переносом BlockNote заменяет selection на блочное:
`NodeSelection` для одного блока либо multi-node selection для диапазона. Это
деталь реализации `0.54.0`; совместимая реализация может использовать другую
внутреннюю модель, если наблюдаемое поведение совпадает.

## Drag preview

После начала drag возле указателя показывается визуальная копия всего
перетаскиваемого диапазона.

- Preview содержит только перемещаемые блоки, а не соседние элементы.
- Preview не является частью документа и не влияет на сериализацию.
- Встроенные `iframe`, `embed` и `object` исключаются из preview: это не удаляет
  соответствующее содержимое из переносимых блоков.
- После `dragend` временный DOM preview удаляется.

## Форматы DataTransfer

Стандартный BlockNote записывает в `DataTransfer` три представления:

| MIME type | Назначение |
| --- | --- |
| `blocknote/html` | Внутреннее представление структуры для BlockNote-редакторов. |
| `text/html` | Interoperable HTML для внешних приложений. |
| `text/plain` | Упрощённое Markdown/plain-text представление. |

Для операции устанавливается `effectAllowed = "move"`. Внутри одного
редактора и между совместимыми BlockNote-редакторами операция является
перемещением, а не копированием.

Входящие значения `text/html` и `text/plain` считаются недоверенными и должны
проходить те же правила очистки и импорта, что обычная вставка. Наличие
произвольного `blocknote/html` само по себе не является достаточной границей
доверия для данных из внешнего источника.

## Drop cursor и допустимая позиция

Во время drag редактор показывает drop cursor в позиции, в которую будет
вставлен диапазон:

- горизонтальный курсор обозначает структурную вставку между блоками;
- inline-курсор обозначает позицию внутри inline-контекста;
- позиция должна учитывать схему документа и размер переносимого фрагмента;
- запрещённая схемой позиция не должна становиться точкой drop;
- в read-only редакторе курсор не показывается и документ не меняется;
- после `drop`, `dragend`, ухода указателя из редактора или размонтирования
  редактора курсор удаляется.

Установленная версия BlockNote позволяет настроить ширину и цвет курсора,
исключить DOM-поддерево CSS-классом `bn-drag-exclude` и переопределить расчёт
через `computeDropPosition`. Возврат `null` из hook запрещает drop в данной
позиции и скрывает курсор. Это расширенная настройка реализации, а не часть
публичной JSON-модели блока.

## Результат drop в одном редакторе

При успешном drop:

- исходный диапазон удаляется со старой позиции и вставляется в новую;
- перенос в ту же позицию не меняет содержимое документа;
- порядок блоков, inline content, props, ID и дочерние деревья сохраняются;
- новая вложенность определяется фактической структурной drop position;
- в документе не остаются пустые технические обёртки;
- изменение является одной смысловой операцией истории и отменяется одним
  `undo`; `redo` повторяет перенос;
- обычный механизм сохранения редактора записывает новое дерево в
  `localStorage`.

Drop рядом с вложенными блоками может изменить родителя перемещаемого диапазона.
Курсор обязан до отпускания указателя визуально отличать такую позицию от
перестановки на текущем уровне.

## Перенос между редакторами

BlockNote поддерживает перенос между несколькими совместимыми экземплярами
редактора на одной странице.

- Целевой редактор восстанавливает блочную структуру из внутреннего
  `blocknote/html` и выбирает позицию между блоками согласно своей схеме.
- Selection целевого редактора не должно приводить к удалению ранее выбранного,
  но не относящегося к drag содержимого.
- После успешного drop исходный редактор удаляет перенесённый диапазон.
- Если целевая схема не поддерживает тип блока или его содержимое, операция
  должна быть отклонена либо пройти через явно заданную нормализацию импорта;
  тихая потеря content, props или children недопустима.
- Каждый затронутый редактор самостоятельно запускает обновление своего
  persistence-состояния.

BlockNote `0.54.0` выбирает ближайший экземпляр редактора как потенциальную
цель, даже если указатель находится немного снаружи его DOM-границ. Порог
`250px` и синтетические DOM-события, которыми реализовано это поведение, —
внутренние детали и не являются обязательным API-контрактом надстройки.

Если drop завершился вне совместимого редактора, обработка внешним приложением
опирается на `text/html` или `text/plain`. Такая операция не должна ошибочно
удалять блоки из исходного документа без подтверждённого move/drop.

## Отмена и неуспешный drop

Документ не изменяется, если:

- drag был отменён клавишей `Escape`;
- указатель отпущен в недопустимой позиции;
- `DataTransfer` недоступен;
- исходный блок больше не существует;
- целевой редактор находится в read-only режиме;
- пользовательский `computeDropPosition` вернул `null`.

После любого завершения операции необходимо очистить drag preview, drop cursor,
признак исходного редактора и временное состояние drag во всех участвовавших
экземплярах.

## Клавиатурная альтернатива

Drag-and-drop не должен быть единственным способом переставить блоки.
BlockNote предоставляет следующие команды:

| Действие | Сочетание | API |
| --- | --- | --- |
| Переместить выбранные блоки вверх | `Shift+Mod+ArrowUp` | `moveBlocksUp()` |
| Переместить выбранные блоки вниз | `Shift+Mod+ArrowDown` | `moveBlocksDown()` |
| Увеличить вложенность | `Tab` | `nestBlock()` |
| Уменьшить вложенность | `Shift+Tab` | `unnestBlock()` |

`Mod` означает `Cmd` на macOS и `Ctrl` на Windows/Linux. Перемещение вверх или
вниз применяет те же инварианты сохранения данных и должно образовывать одну
операцию undo/redo. Это функциональная альтернатива, но не гарантия достижения
любой произвольной позиции drop только одной клавишей.

## Контракт кастомного Side Menu

Если стандартный React-компонент заменён, кастомный drag handle должен:

1. получать текущий блок из состояния `SideMenuExtension`;
2. иметь `draggable={true}`;
3. передавать `dragstart` и блок в `blockDragStart`;
4. вызывать `blockDragEnd` на `dragend`;
5. фиксировать и освобождать меню при открытии и закрытии меню действий;
6. сохранять доступное имя и видимый feedback начала drag.

Vanilla JS-интеграция подписывается на store расширения и самостоятельно
рисует UI. Публичный код приложения не должен обращаться к внутренним полям
ProseMirror selection ради запуска переноса.

## Граница ответственности

Эта спецификация определяет:

- выбор одного или нескольких перемещаемых блоков;
- взаимодействие drag handle, preview и drop cursor;
- перенос внутри одного и между несколькими редакторами;
- структурные инварианты, историю и очистку временного состояния;
- минимальный контракт кастомного Side Menu.

Она не определяет:

- внешний вид конкретной UI-библиотеки;
- формат UUID;
- drag-and-drop файлов с рабочего стола;
- сортировку произвольных виджетов вне редактора;
- преобразование несовместимых схем без отдельной спецификации импорта.

## Критерии приёмки

1. Hover над редактируемым блоком показывает Side Menu с доступным drag handle.
2. Click по handle открывает меню действий, а drag запускает перенос.
3. Drag блока вне multi-block selection переносит только этот блок вместе с его
   дочерним деревом.
4. Drag блока внутри multi-block selection переносит весь диапазон и сохраняет
   порядок блоков.
5. Выделение через разные уровни вложенности не оставляет повреждённые или
   пустые структурные обёртки.
6. Preview содержит только переносимый диапазон и удаляется после операции.
7. Во время drag видна однозначная допустимая позиция вставки.
8. Drop в запрещённую позицию и drop в read-only редактор не меняют документ.
9. Drop в том же редакторе сохраняет ID, type, props, content и children.
10. Успешный перенос отменяется одним `undo` и возвращается одним `redo`.
11. Новая структура после drop сохраняется в `localStorage` общим persistence-
    механизмом редактора.
12. Перенос между двумя совместимыми редакторами вставляет диапазон в целевой и
    удаляет его из исходного редактора без удаления постороннего selection.
13. `DataTransfer` содержит внутренний HTML, interoperable HTML и plain text.
14. Отмена drag не изменяет документ и очищает все временные UI-элементы.
15. `Shift+Mod+ArrowUp` и `Shift+Mod+ArrowDown` доступны как клавиатурная
    альтернатива перестановке блоков.
16. Кастомный Side Menu может запустить и завершить перенос через контракт
    `SideMenuExtension`, не используя приватные структуры ProseMirror.

## Требуемые тесты реализации

- перенос одного корневого блока вверх и вниз;
- перенос родителя с несколькими уровнями children;
- перенос нескольких соседних блоков;
- выделение, начинающееся и заканчивающееся на разных уровнях вложенности;
- drop до первого, между соседними и после последнего блока;
- drop с изменением вложенности;
- drop в исходную позицию;
- отмена через `Escape` и drop в запрещённую область;
- read-only target;
- перенос между двумя редакторами с разными активными selection;
- несовместимые схемы исходного и целевого редакторов;
- один шаг undo/redo;
- восстановление новой структуры из `localStorage` после перезагрузки;
- очистка preview и cursor после drop, dragend и unmount;
- keyboard-only перемещение вверх и вниз.
