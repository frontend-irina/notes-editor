# Inline Content

## Назначение

Inline content — содержимое текстовых блоков, включая `paragraph`, `heading` и элементы списков. Реализация должна повторять публичную модель и поведение BlockNote.

Источник поведения: [BlockNote — Inline Content](https://www.blocknotejs.org/docs/features/blocks/inline-content).

## Модель данных

В стандартной схеме BlockNote inline content состоит из стилизованного текста и ссылок:

```ts
type InlineContent = StyledText | Link;

type StyledText = {
  type: "text";
  text: string;
  styles: Styles;
};

type Link = {
  type: "link";
  content: StyledText[];
  href: string;
};

type Styles = {
  bold?: boolean;
  italic?: boolean;
  underline?: boolean;
  strike?: boolean;
  code?: boolean;
  textColor?: string;
  backgroundColor?: string;
};
```

В сериализованном JSON неактивные стили опускаются. Поэтому обычный текст содержит `styles: {}`, хотя концептуальные значения булевых стилей по умолчанию равны `false`, а цветов — `"default"`.

## StyledText

- `type` всегда равен `"text"`.
- `text` содержит строку текста.
- `styles` содержит только стили этого фрагмента.
- Один визуальный текстовый диапазон разбивается на несколько `StyledText`, если набор активных стилей меняется.
- Смежные текстовые фрагменты с одинаковым набором стилей должны нормализоваться в один фрагмент.
- Пустые текстовые фрагменты не должны сохраняться в публичном JSON.
- Пробелы являются частью `text` и не должны теряться при нормализации.

## Link

- `type` всегда равен `"link"`.
- `href` содержит адрес ссылки.
- `content` содержит отображаемый текст ссылки в виде массива `StyledText`.
- Разные части текста одной ссылки могут иметь разные стили.
- Ссылка не должна содержать другую ссылку.
- При удалении ссылки отображаемый текст сохраняется как обычный `StyledText`.
- Изменение текста ссылки не должно само по себе менять `href`.
- Если пользователь задаёт собственный обработчик клика, стандартное открытие ссылки отключается и вызывается этот обработчик.
- Без собственного обработчика BlockNote по умолчанию открывает ссылку в новом окне.

## Стандартные стили

| Свойство | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `bold` | `boolean` | `false` | Полужирное начертание. |
| `italic` | `boolean` | `false` | Курсив. |
| `underline` | `boolean` | `false` | Подчёркивание. |
| `strike` | `boolean` | `false` | Зачёркивание. |
| `code` | `boolean` | `false` | Inline code. |
| `textColor` | `string` | `"default"` | Цвет текста. |
| `backgroundColor` | `string` | `"default"` | Цвет фона текста. |

Стили могут комбинироваться. Их порядок применения не должен влиять на публичное JSON-представление.

## Поведение выделения и ввода

- Применение стиля к непустому выделению изменяет только выделенный диапазон и при необходимости разделяет `StyledText`.
- Повторное применение активного булевого стиля снимает его с выбранного диапазона.
- Если выделение пустое, выбранный стиль становится активным для последующего ввода.
- Ввод внутри styled text наследует активные стили позиции курсора.
- Ввод внутри ссылки продолжает ссылку, пока пользователь не завершит её согласно стандартному поведению BlockNote/Tiptap.
- Удаление текста через границу двух совместимых фрагментов приводит к их нормализации.
- Операции undo/redo должны атомарно восстанавливать изменения текста, ссылок и стилей.

## Сокращённая форма входных данных

API может принимать строку как сокращённую запись обычного текста там, где BlockNote принимает `PartialInlineContent`:

```ts
const input = "Обычный текст";
```

После нормализации публичное представление имеет полный вид:

```json
[
  {
    "type": "text",
    "text": "Обычный текст",
    "styles": {}
  }
]
```

Для ссылки входной API BlockNote также может принимать строковое `content`; в публичном нормализованном документе содержимое ссылки представляется массивом `StyledText`.

## Пример

```json
[
  {
    "type": "text",
    "text": "Обычный ",
    "styles": {}
  },
  {
    "type": "text",
    "text": "жирный текст",
    "styles": {
      "bold": true
    }
  },
  {
    "type": "text",
    "text": " и ",
    "styles": {}
  },
  {
    "type": "link",
    "href": "https://example.com",
    "content": [
      {
        "type": "text",
        "text": "ссылка",
        "styles": {}
      }
    ]
  }
]
```

## Импорт и экспорт HTML

- Текстовые узлы импортируются как `StyledText`.
- Поддерживаемая семантическая и стилевая HTML-разметка преобразуется в соответствующие `Styles`.
- `<a href="…">` импортируется как `Link`, а поддерживаемое форматирование внутри ссылки сохраняется в её `StyledText[]`.
- Экспорт должен сохранять текст, ссылки и все поддерживаемые комбинации стилей.
- Цикл JSON → HTML → JSON должен сохранять семантически эквивалентное inline-содержимое, даже если разбиение на соседние текстовые фрагменты было нормализовано.

## Граница ответственности

- `InlineContent[]` описывает только содержимое текущего блока.
- Переносы между блоками, вложенность и идентификаторы блоков не относятся к inline content.
- Цвет блока в `props` и цвет отдельного фрагмента в `styles` — разные уровни данных. Стиль фрагмента имеет визуальный приоритет внутри своего диапазона.
- Пользовательские inline-типы будут описаны отдельно и не входят в обязательный объём стандартной схемы.

## Критерии приёмки

1. Обычный текст, стилизованный текст и ссылки сериализуются в формате BlockNote.
2. Все семь стандартных стилей поддерживают применение, снятие, комбинирование и сохранение.
3. Форматирование непустого выделения не затрагивает текст вне выделения.
4. Смежные совместимые текстовые фрагменты нормализуются без изменения видимого текста.
5. Ссылка сохраняет `href`, отображаемый текст и стили после сериализации и загрузки.
6. Удаление ссылки сохраняет её отображаемый текст.
7. Импорт и экспорт HTML не теряют поддерживаемую семантику.
8. Undo/redo корректно восстанавливает текст, стили и ссылки.
