# Formatting Toolbar

## Назначение

Formatting Toolbar — контекстная панель для изменения типа выбранных блоков, форматирования inline content и выполнения доступных операций над блоками.

Реализация надстройки над Tiptap должна повторять наблюдаемое поведение и возможности стандартной Formatting Toolbar BlockNote.

Основной источник: [BlockNote — Formatting Toolbar](https://www.blocknotejs.org/docs/react/components/formatting-toolbar).

Связанные спецификации:

- [Paragraph](./blocks/paragraph/paragraph.md);
- [Inline Content](./inline-content.md);
- [Идентификатор блока](./block-id.md).

## Режим отображения

По умолчанию Formatting Toolbar является плавающей контекстной панелью.

- Панель появляется при выделении текста в редакторе.
- Панель располагается рядом с текущим выделением — выше или ниже него в зависимости от доступного места.
- Позиция панели должна обновляться при изменении выделения, прокрутке, изменении размеров viewport или геометрии редактора.
- Панель не должна перекрывать выделение, если для неё доступна альтернативная позиция.
- Если выделение больше не удовлетворяет условиям показа, панель скрывается.
- Панель не отображается для выбранного блока без inline content, если ни одно действие панели к нему не применимо.
- При выделении нескольких блоков набор элементов определяется возможностями всех выбранных блоков и текущего editor state.
- Открытое дочернее меню панели, например выбор цвета или типа блока, считается частью взаимодействия с панелью и не должно приводить к её преждевременному закрытию.

Позиционирование и видимость являются ответственностью контроллера панели, аналогичного `FormattingToolbarController`. Визуальное содержимое панели должно быть отделено от логики её показа.

Статический режим Formatting Toolbar не входит в требования проекта. Панель должна использоваться только как контекстный плавающий интерфейс, привязанный к текущему выделению.

## Стандартный состав панели

Стандартная панель BlockNote содержит следующие элементы в установленном порядке:

1. `BlockTypeSelect` — выбор или преобразование типа блока;
2. `FileCaptionButton` — изменение подписи файлового блока, показывается только когда применим;
3. `FileReplaceButton` — замена файла, показывается только когда применим;
4. `BasicTextStyleButton` для `bold`;
5. `BasicTextStyleButton` для `italic`;
6. `BasicTextStyleButton` для `underline`;
7. `BasicTextStyleButton` для `strike`;
8. `TextAlignButton` для `left`;
9. `TextAlignButton` для `center`;
10. `TextAlignButton` для `right`;
11. `ColorStyleButton` — выбор цвета текста и фона;
12. `NestBlockButton` — увеличение вложенности блока;
13. `UnnestBlockButton` — уменьшение вложенности блока;
14. `CreateLinkButton` — создание или изменение ссылки.

Кнопка inline code не входит в показанный стандартный состав панели BlockNote. Она должна добавляться как настраиваемый `BasicTextStyleButton` с типом `code`, если продукту требуется управление code style из toolbar.

Конкретный элемент должен отображаться только тогда, когда действие поддерживается текущей схемой и применимо к selection. Недоступное, но релевантное действие может быть disabled; нерелевантное текущему контексту действие должно быть скрыто.

## Block Type Select

`BlockTypeSelect` является первым элементом стандартной панели.

- Список содержит типы блоков, в которые допустимо преобразовать текущий выбранный блок или блоки.
- Текущий тип блока должен быть визуально обозначен как выбранный.
- Выбор пункта преобразует выбранный блок в соответствующий тип через API редактора.
- При преобразовании сохраняются совместимые inline content, стили, props и ID блока.
- Недоступные для выбранного контекста типы не должны предлагаться как выполнимые действия.
- Названия и tooltip должны использовать словарь локализации редактора.

Стандартный список для текущей схемы содержит:

| Пункт | Результат | Сочетание |
| --- | --- | --- |
| Параграф | Преобразует совместимый текстовый блок в `paragraph` | `Mod+Alt+0` |
| Заголовок 1 | Преобразует блок в `heading` с `level: 1` | `Mod+Alt+1` |
| Заголовок 2 | Преобразует блок в `heading` с `level: 2` | `Mod+Alt+2` |
| Заголовок 3 | Преобразует блок в `heading` с `level: 3` | `Mod+Alt+3` |
| Заголовок 4 | Преобразует блок в `heading` с `level: 4` | `Mod+Alt+4` |
| Заголовок 5 | Преобразует блок в `heading` с `level: 5` | `Mod+Alt+5` |
| Заголовок 6 | Преобразует блок в `heading` с `level: 6` | `Mod+Alt+6` |
| Цитата | Преобразует совместимый текстовый блок в `quote` | `Mod+Alt+Q` |

- Когда cursor или selection находятся в одном heading, на кнопке
  `BlockTypeSelect` отображается «Заголовок N», а соответствующий пункт меню имеет
  selected-состояние.
- Если selection охватывает разные типы блоков или headings разных уровней,
  кнопка отображает «Несколько типов» и ни один отдельный уровень не считается
  выбранным.
- Выбор другого уровня изменяет `props.level`, сохраняя `id`, `content`, inline
  styles, совместимые стандартные props и `children`.
- Открытие меню и выбор Heading не должны уничтожать selection. После выполнения
  команды focus возвращается в редактор.

Список пунктов должен быть настраиваемым. Пользователь API может:

- получить стандартные пункты на основе словаря;
- сохранить стандартные пункты и добавить собственные;
- заменить список полностью;
- добавить тип блока из пользовательской схемы, если для него определено корректное преобразование.

Настройка пунктов `BlockTypeSelect` не должна требовать полной замены остальных стандартных кнопок панели.

## Основные текстовые стили

Каждый `BasicTextStyleButton` управляет одним булевым стилем из [inline-content.md](./inline-content.md).

- Нажатие применяет стиль к выделенному тексту.
- Если весь применимый selection имеет стиль, нажатие снимает его.
- Если стиль активен только на части selection, кнопка должна отражать смешанное состояние либо состояние, согласованное с BlockNote, а действие должно привести selection к единому ожидаемому значению.
- `isSelected`/active state определяется текущими активными стилями редактора, а не локальным React state кнопки.
- Операция должна участвовать в undo/redo как обычное изменение документа.
- Кнопка скрывается или становится недоступной, если выбранные блоки не содержат форматируемого inline content либо стиль отсутствует в схеме.

Обязательные стандартные стили панели: `bold`, `italic`, `underline`, `strike`.

## Выравнивание

- Стандартная панель предоставляет действия `left`, `center` и `right`.
- Выбор значения обновляет `textAlignment` выбранного блока или всех применимых выбранных блоков.
- Активное выравнивание визуально отмечается.
- Действие не должно изменять inline content или ID блока.
- Кнопки скрываются или недоступны для типов блоков, которые не поддерживают соответствующий prop.
- Значение `justify` поддерживается моделью `DefaultProps`, но не представлено отдельной кнопкой в стандартном составе, показанном документацией Formatting Toolbar. Оно может быть добавлено при кастомизации.

## Цвет текста и фона

`ColorStyleButton` открывает интерфейс выбора `textColor` и `backgroundColor` для inline content.

- Изменение цвета применяется к текущему selection.
- Цвет текста и цвет фона являются независимыми значениями.
- Выбранные цвета должны отражаться в active state интерфейса.
- Должен быть доступен возврат к значениям по умолчанию.
- Изменения сериализуются в `StyledText.styles`, а не в props блока.
- Цветовые действия недоступны, если selection не содержит поддерживаемого inline content или соответствующие стили отсутствуют в схеме.

Не следует смешивать inline-цвета из этой кнопки с `textColor` и `backgroundColor` уровня блока.

## Вложенность блоков

### NestBlockButton

- Увеличивает уровень вложенности выбранного блока или группы блоков.
- Действие доступно только при наличии допустимого предыдущего sibling, который может стать родителем.
- Перемещение не изменяет ID, content и props блока.

### UnnestBlockButton

- Уменьшает уровень вложенности выбранного блока или группы блоков.
- Действие доступно только для вложенных блоков.
- Перемещение не изменяет ID, content и props блока.

Обе команды должны корректно поддерживать multi-block selection и undo/redo. Кнопка должна быть disabled или скрыта, если соответствующая структурная команда невозможна.

## Создание ссылки

- `CreateLinkButton` доступна для selection с inline content.
- Для непустого текстового выделения действие позволяет задать `href` и превратить выделенный текст в `Link`.
- При вызове на существующей ссылке интерфейс должен позволять изменить её адрес без потери отображаемого текста и стилей.
- Ссылки не могут быть вложены друг в друга.
- Результат сериализуется согласно [inline-content.md](./inline-content.md).
- Взаимодействие с вводом адреса не должно терять исходный text selection до применения команды.

Поведение просмотра ссылки при hover относится к отдельному Link Toolbar и не должно смешиваться с Formatting Toolbar.

## Файловые действия

`FileCaptionButton` и `FileReplaceButton` являются контекстными элементами:

- они отображаются только для файловых блоков, которые поддерживают соответствующую операцию;
- caption изменяет подпись выбранного файла;
- replace запускает предусмотренный редактором сценарий замены файла;
- эти элементы не должны отображаться для обычного paragraph только ради сохранения постоянной ширины панели;
- детальное поведение файлов будет определено в спецификациях соответствующих блоков и File Panel.

## Состояния элементов управления

Каждый элемент панели должен поддерживать следующие состояния, если они применимы:

- `active`/`selected` — формат или значение активно;
- `inactive` — действие доступно, но не активно;
- `disabled` — действие относится к контексту, но сейчас невыполнимо;
- `hidden` — действие не относится к текущему selection или отсутствует в схеме;
- `expanded` — дочернее меню элемента открыто.

Состояния должны вычисляться из editor state реактивно. Они обновляются после изменения selection, документа, схемы или доступности команды.

Нажатие кнопки панели не должно без необходимости забирать focus у редактора или уничтожать selection до выполнения команды. После применения обычного форматирования редактор должен оставаться готовым к продолжению ввода.

## Горячие клавиши

Действия Formatting Toolbar должны быть доступны горячими клавишами, аналогичными BlockNote. Горячие клавиши являются командами редактора: они должны работать при focus внутри редактора независимо от того, отображается ли в данный момент панель.

`Mod` означает:

- `Cmd` на macOS;
- `Ctrl` на Windows и Linux.

### Форматирование inline content

| Действие | Сочетание | Результат |
| --- | --- | --- |
| Полужирный | `Mod+B` | Переключает стиль `bold`. |
| Курсив | `Mod+I` | Переключает стиль `italic`. |
| Подчёркивание | `Mod+U` | Переключает стиль `underline`. |
| Зачёркивание | `Mod+Shift+S` | Переключает стиль `strike`. |
| Создать или изменить ссылку | `Mod+K` | Открывает popover ссылки для текущего selection. |

Для текстовых стилей применяются те же правила selection и active state, что и при нажатии соответствующей кнопки. Команда должна предотвращать стандартное действие браузера только тогда, когда она действительно применима и обработана редактором.

`Mod+K` должен:

- открывать тот же popover, что и `CreateLinkButton`;
- сохранять текущее text selection на время работы с полем URL;
- при существующей ссылке загружать её текущий `href`;
- не открывать popover, если ссылки отсутствуют в схеме или selection не поддерживает inline content;
- вызывать `preventDefault`, когда shortcut обработан, чтобы не запускать браузерный поиск или переход к адресу.

В BlockNote inline code поддерживает `Mod+E` на уровне редактора/Tiptap, но кнопка code не входит в стандартный состав Formatting Toolbar. Если кнопка code добавлена при кастомизации, её tooltip должен показывать `Mod+E`, а нажатие и shortcut должны вызывать одну команду `toggleCode`.

### Вложенность

| Действие | Сочетание | Результат |
| --- | --- | --- |
| Увеличить вложенность | `Tab` | Выполняет `nestBlock`, если структурная операция допустима. |
| Уменьшить вложенность | `Shift+Tab` | Выполняет `unnestBlock`, если блок вложен. |

Когда Formatting Toolbar или её дочерний popover открыт и focus переводится на элементы панели, `Tab` и `Shift+Tab` должны использоваться для клавиатурной навигации по интерактивным элементам, а не изменять вложенность блока. После возврата focus в редактор они снова выполняют nest/unnest.

### Преобразование типа блока

Горячие клавиши преобразования должны выполнять те же команды, что и выбор пункта `BlockTypeSelect`, и сохранять совместимые content, props, children и ID блока.

| Тип блока | Сочетание BlockNote |
| --- | --- |
| Paragraph | `Mod+Alt+0` |
| Heading 1–6 | `Mod+Alt+1` … `Mod+Alt+6` |
| Quote | `Mod+Alt+Q` |
| Code block | `Mod+Alt+C` |
| Toggle list item | `Mod+Shift+6` |
| Numbered list item | `Mod+Shift+7` |
| Bullet list item | `Mod+Shift+8` |
| Check list item | `Mod+Shift+9` |

Shortcut регистрируется только для типа блока, присутствующего в активной схеме. Если преобразование текущего блока невозможно, обработчик возвращает `false` и не должен изменять документ.

### Управление панелью с клавиатуры

- `Tab` перемещает focus вперёд по видимым интерактивным элементам панели.
- `Shift+Tab` перемещает focus назад.
- Скрытые и disabled элементы не должны становиться остановками клавиатурной навигации.
- `Enter` и `Space` активируют кнопку с focus.
- `Escape` закрывает открытый dropdown/popover; если дочернее меню уже закрыто, закрывает Formatting Toolbar.
- После закрытия панели клавишей `Escape` focus возвращается в редактор, а исходное selection сохраняется.
- Горячая клавиша форматирования не должна переводить focus на кнопку панели.

### Отображение сочетаний

- Tooltip кнопки должен показывать её актуальное сочетание как secondary tooltip.
- На macOS `Mod` отображается как `Cmd` или системный символ команды; на Windows/Linux — как `Ctrl`.
- Отображаемое сочетание должно соответствовать фактически зарегистрированному обработчику.
- Если для действия shortcut не зарегистрирован, пустую или вымышленную подсказку показывать нельзя.
- Локализация может менять подписи действий, но не должна менять семантику shortcut.

Фактическое сочетание BlockNote для зачёркивания — `Mod+Shift+S`. В русской локали BlockNote 0.54 secondary tooltip содержит несовпадающее значение `Mod+Shift+X`; эту ошибку локализации повторять не требуется.

### Приоритет и конфликты

- Обработчики работают только когда focus находится в редакторе или контролируемом popover панели.
- Shortcut не должен срабатывать во время composition/IME, если это нарушает ввод символа.
- Disabled или неприменимая команда не должна создавать транзакцию в истории.
- Одно нажатие создаёт не более одной смысловой транзакции undo/redo.
- Пользовательская конфигурация может переопределить shortcut, но конфликт должен разрешаться детерминированно и документироваться в публичном API.
- В read-only режиме shortcuts изменения документа не выполняются.

## Кастомизация

Публичный UI API должен позволять:

- отключить стандартную Formatting Toolbar;
- передать пользовательский React-компонент панели в контроллер;
- использовать контейнер `FormattingToolbar` со стандартными дочерними элементами;
- заменить стандартный набор элементов, передав собственные `children`;
- вставлять пользовательские кнопки между стандартными элементами;
- изменить только пункты `BlockTypeSelect`, сохранив стандартный toolbar;
- условно возвращать `null` из пользовательского элемента на основании состояния выбранных блоков;
- получать примитивы UI через components context, чтобы пользовательские кнопки визуально соответствовали теме редактора.

Если `FormattingToolbar` используется без `children`, он отображает стандартный набор элементов. Если переданы `children`, они заменяют стандартное содержимое, а порядок определяется порядком дочерних элементов.

## Контракт пользовательской кнопки

Пользовательская кнопка должна иметь доступ как минимум к:

- экземпляру редактора;
- актуальному selection и выбранным блокам;
- активным inline styles и props блока;
- команде, выполняемой по нажатию;
- состоянию `isSelected`;
- состоянию disabled или условию скрытия;
- локализованным label и tooltip;
- стандартному UI-примитиву кнопки текущей темы.

Пользовательская кнопка не должна подписываться на весь editor state, если ей нужна только небольшая его часть. Необходимо использовать selector-подписку, чтобы избежать лишних React-рендеров.

## Доступность

- Панель и её группы должны иметь корректные ARIA-роли и доступное имя.
- Каждая кнопка должна иметь доступный label независимо от наличия иконки.
- Tooltip не заменяет `aria-label`.
- Active state должен быть доступен assistive technologies, например через `aria-pressed`.
- Disabled state должен быть семантически отражён.
- Dropdown-элементы должны сообщать `aria-expanded` и связь с меню.
- Пользователь должен иметь возможность пройти по элементам клавиатурой и закрыть дочернее меню клавишей `Escape`.
- Focus при закрытии дочернего меню должен возвращаться предсказуемо и не терять контекст редактирования.

## Граница ответственности

Formatting Toolbar:

- отображает состояние редактора;
- вызывает публичные команды форматирования и структурных изменений;
- управляет только UI конкретных действий.

Formatting Toolbar не должна:

- хранить копию документа;
- самостоятельно изменять ProseMirror DOM;
- реализовывать сериализацию;
- генерировать или изменять ID блоков;
- дублировать алгоритмы команд редактора;
- отвечать за hover-интерфейс ссылок, File Panel или Block Side Menu.

## Критерии приёмки

1. При выделении текста появляется плавающая Formatting Toolbar, расположенная рядом с selection.
2. При снятии выделения или переходе в неприменимый контекст панель скрывается.
3. Стандартные элементы представлены в порядке и с условной видимостью, описанными выше.
4. `bold`, `italic`, `underline` и `strike` применяются и снимаются с выделенного текста, а active state обновляется реактивно.
5. Выравнивание изменяет только props применимых блоков и сохраняет их ID и content.
6. Выбранные inline-цвета сохраняются в `StyledText.styles` после сериализации и загрузки.
7. Создание и изменение ссылки сохраняет отображаемый текст и его стили.
8. Nest и unnest изменяют только структуру документа и корректно участвуют в undo/redo.
9. Нерелевантные файловые элементы не отображаются для paragraph.
10. Панель можно полностью отключить и заменить пользовательским React-компонентом.
11. Передача собственных `children` заменяет стандартный набор и сохраняет заданный порядок.
12. Список `BlockTypeSelect` можно расширить без замены остальных элементов панели.
13. Пользовательская кнопка может реактивно вычислять selected state и условную видимость из editor state.
14. Взаимодействие с кнопками и дочерними меню не приводит к потере selection до выполнения команды.
15. Основные действия панели доступны с клавиатуры и имеют корректные доступные имена и состояния.
16. `Mod+B`, `Mod+I`, `Mod+U` и `Mod+Shift+S` выполняют те же toggle-команды, что и соответствующие кнопки.
17. `Mod+K` открывает popover ссылки, сохраняет selection и предотвращает стандартное действие браузера.
18. `Tab` и `Shift+Tab` выполняют nest/unnest при focus в редакторе, но навигацию по controls при focus внутри открытой панели.
19. `Escape` закрывает дочернее меню или панель и возвращает focus в редактор без потери selection.
20. Shortcuts `BlockTypeSelect` преобразуют только поддерживаемые схемой блоки и сохраняют ID.
21. Tooltip каждого действия показывает фактически зарегистрированное платформенное сочетание.
22. В read-only режиме горячие клавиши не изменяют документ.
23. `BlockTypeSelect` содержит Heading 1–6, показывает текущий уровень и позволяет
    сменить его без потери `id`, `content`, inline styles, props и `children`.

## Вопросы для проверки по эталону

Документация BlockNote не формализует все пограничные состояния. Перед полной реализацией необходимо зафиксировать наблюдаемое поведение BlockNote для следующих случаев:

- частично активный стиль в selection;
- selection через блоки разных типов;
- selection, одновременно включающий inline и non-inline блоки;
- приоритет позиции панели при недостатке места сверху и снизу;
- точные условия скрытия против disabled для каждой стандартной кнопки;
- поведение panel focus при клике, `Escape`, undo/redo и восстановлении selection;
- групповой nest/unnest для несмежных или разноуровневых блоков.

Результаты такого сравнения следует добавить в этот документ до объявления полной совместимости с BlockNote.
