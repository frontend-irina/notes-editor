# Добавление блоков через `+` и Slash Menu

## Назначение

Документ определяет целевое поведение меню добавления и преобразования блоков
в надстройке над Tiptap. Эталоном является стандартный интерфейс BlockNote:

- кнопка `+` в Block Side Menu;
- Suggestion Menu с триггером `/`, далее — Slash Menu.

Основные источники:

- [BlockNote — Block Side Menu](https://www.blocknotejs.org/docs/react/components/side-menu);
- [BlockNote — Suggestion Menus](https://www.blocknotejs.org/docs/react/components/suggestion-menus);
- [BlockNote — Adding Slash Menu Items](https://www.blocknotejs.org/examples/ui-components/suggestion-menus-slash-menu-items);
- [BlockNote — Manipulating Blocks](https://www.blocknotejs.org/docs/reference/editor/manipulating-content).

Требования дополнительно сверены с исходным кодом установленной версии
`@blocknote/core@0.54.0` и `@blocknote/react@0.54.0`. Внутренние названия
ProseMirror-плагинов не являются публичным API проекта.

Связанные спецификации:

- [Drag-and-drop блоков](../drag-and-drop.md);
- [Идентификатор блока](../block-id.md);
- [Formatting Toolbar](../toolbar.md);
- [Paragraph](../blocks/paragraph/paragraph.md);
- [Heading](../blocks/heading/heading.md);
- [Quote](../blocks/quote/quote.md);
- [Типы списков](../blocks/list-types/list-types.md).

## Термины

- **Side Menu** — меню слева от блока, которое появляется при наведении;
- **Add Block Button** — кнопка `+` в Side Menu;
- **trigger character** — строка, ввод которой открывает Suggestion Menu;
- **query** — текст после trigger character, используемый для фильтрации;
- **Slash Menu** — Suggestion Menu с trigger character `/`;
- **menu item** — команда, которая создаёт, преобразует или иначе изменяет блок.

## Общий принцип

Кнопка `+` и ввод `/` открывают одно и то же Slash Menu и используют один
набор команд. Они отличаются подготовкой документа перед открытием:

| Сценарий | Изменение перед открытием | Начальный query |
| --- | --- | --- |
| `/` введён с клавиатуры | `/` вставляется в текущий inline-блок | пустой |
| `+` у пустого inline-блока | существующий блок сохраняется, курсор переводится в него | пустой |
| `+` у непустого блока | после блока вставляется пустой `paragraph`, курсор переводится в него | пустой |

Оба сценария должны показывать одинаковые доступные пункты для одной схемы
редактора, одинаково фильтровать команды и выполнять один и тот же callback
выбранного пункта.

## Кнопка `+` в Side Menu

### Отображение

- Side Menu появляется слева при наведении на редактируемый блок.
- Стандартный состав начинается с `+`, после которого расположен drag handle.
- Кнопка имеет локализованное доступное имя, например «Добавить блок».
- В read-only и headless-режимах кнопка не должна изменять документ или
  открывать интерактивное меню.
- Собственный Side Menu может заменить или убрать кнопку; отключение
  стандартного UI через `sideMenu={false}` не удаляет программный API блоков.

### Нажатие у пустого блока

BlockNote считает блок пустым для этого сценария, когда его `content` является
массивом без элементов.

После нажатия:

1. новый блок не создаётся;
2. ID существующего блока сохраняется;
3. текстовый курсор переводится в этот блок;
4. открывается Slash Menu с пустым query;
5. символ `/` визуально в content не добавляется.

### Нажатие у непустого блока

После нажатия:

1. сразу после исходного блока на том же структурном уровне вставляется пустой
   блок `paragraph`;
2. новый блок получает новый уникальный ID;
3. курсор переводится в новый блок;
4. открывается Slash Menu с пустым query;
5. исходный блок, его content, props, ID и children не изменяются.

Если пользователь закрывает открытое через `+` меню без выбора команды,
созданный пустой `paragraph` остаётся в документе. Его удаление или объединение
подчиняется общим правилам редактирования пустых блоков.

## Открытие вводом `/`

Slash Menu регистрируется как Suggestion Menu с `triggerCharacter: "/"`.

- Меню открывается после ввода `/` в поддерживаемом редактируемом content.
- Стандартный React UI запрещает открытие внутри `tableContent`.
- Меню не активируется внутри узла с признаком code.
- Введённый `/` остаётся частью временного текста и получает decoration,
  к которой привязывается позиция меню.
- Текст, введённый после `/` в том же блоке, становится query.
- Выделение текста, переход курсора перед триггером, переход в другой блок,
  потеря focus или pointer-selection закрывают меню.
- Во время composition/IME нажатие `Enter` не должно преждевременно выполнять
  команду.

Несколько Suggestion Menu могут использовать разные одно- или многосимвольные
триггеры. Если совпадают несколько вариантов, более длинный trigger character
имеет приоритет.

## Позиционирование

- Меню привязывается к DOM decoration триггера либо к текущему блоку при
  программном открытии без отображаемого триггера.
- Предпочтительная позиция — снизу от триггера, по его левому краю.
- При недостатке места меню может переместиться вверх.
- Меню не должно выходить за границы viewport и получает ограничение по
  доступной высоте.
- Скролл пересчитывает позицию открытого меню.
- Взаимодействие со scrollbar меню не должно снимать focus с редактора.

## Модель пункта меню

Минимальный публичный контракт пункта:

```ts
type SlashMenuItem = {
  title: string;
  onItemClick: () => void;
  subtext?: string;
  badge?: string;
  aliases?: string[];
  group?: string;
  icon?: ReactNode;
};
```

Назначение полей:

| Поле | Поведение |
| --- | --- |
| `title` | Основное локализованное название и часть поискового индекса. |
| `onItemClick` | Команда, выполняемая после выбора. |
| `subtext` | Краткое описание результата. |
| `badge` | Подсказка, обычно сочетание клавиш. |
| `aliases` | Дополнительные локализованные и технические поисковые слова. |
| `group` | Заголовок логической группы. |
| `icon` | Визуальное обозначение команды в React UI. |

Внутренний `key`, используемый стандартным BlockNote для связи со словарём и
иконкой, может быть добавлен реализацией, но не заменяет стабильный `title` и
callback.

## Состав меню

Стандартный набор строится динамически из schema. Пункт показывается только
тогда, когда редактор поддерживает соответствующий тип и необходимые props.

Для текущей схемы проекта обязательны:

| Пункт | Результат | Badge |
| --- | --- | --- |
| Параграф | `paragraph` | `Mod+Alt+0` |
| Заголовок 1…6 | `heading` с выбранным `level` | `Mod+Alt+1`…`6` |
| Цитата | `quote` | — |
| Нумерованный список | `numberedListItem` | `Mod+Shift+7` |
| Маркированный список | `bulletListItem` | `Mod+Shift+8` |
| Контрольный список | `checkListItem` | `Mod+Shift+9` |

Целевой порядок меню фиксирован: сначала Paragraph, затем Heading уровней 1–6,
Quote и в конце типы списков. В UI эти элементы образуют последовательные
группы «Текст», «Заголовки», «Цитаты» и «Списки».

`toggleListItem` и toggle-heading не входят в целевую схему проекта и не
должны появляться в меню. Типы `table`, `codeBlock`, `divider`, file/media и
прочие пункты добавляются только после появления соответствующих block specs.

Порядок пунктов совпадает с порядком массива, возвращаемого поставщиком.
Соседние пункты с одинаковым `group` отображаются под одним заголовком. Если
одинаковая группа разделена другой группой, UI показывает несколько секций с
одинаковым названием — автоматическая перегруппировка не выполняется.

## Фильтрация и асинхронная загрузка

Стандартная фильтрация BlockNote:

- регистр не учитывается;
- пункт подходит, если query является подстрокой `title` или любого `alias`;
- порядок подходящих пунктов не меняется;
- пустой query возвращает весь доступный список;
- локализованные title и aliases участвуют в поиске наравне с английскими.

`getItems(query)` является асинхронным. Реализация должна:

- показывать loading-state при первом и последующих запросах;
- игнорировать ответ устаревшего запроса, если query уже изменился;
- показывать локализованное пустое состояние, когда актуальный запрос не дал
  результатов;
- сбрасывать активный индекс на первый пункт при изменении query;
- не выполнять item из устаревшего массива.

В BlockNote `0.54.0` меню автоматически закрывается после более чем трёх
последовательных дополнительных символов query без результатов. Это наблюдаемая
деталь установленной версии; совместимая реализация должна закрепить её тестом,
если воспроизводит буквально.

Опция `minQueryLength` может отложить показ до минимальной длины query. При
значении больше нуля пробел сразу после trigger character также не показывает
меню. Для стандартного Slash Menu минимальная длина не задана.

## Навигация и выбор

| Действие | Результат |
| --- | --- |
| `ArrowDown` | Следующий пункт; после последнего — первый. |
| `ArrowUp` | Предыдущий пункт; перед первым — последний. |
| `PageDown` | Последний пункт. |
| `PageUp` | Первый пункт. |
| `Enter` | Выполнить выбранный пункт, кроме активной IME composition. |
| Click | Выполнить указанный пункт. |
| `Escape` | Закрыть меню без выполнения команды. |

Выбранный пункт имеет `aria-selected="true"`. Редактор во время открытия
получает `aria-expanded`, `aria-controls`, а активный пункт связывается с ним
через `aria-activedescendant`. Focus остаётся в contenteditable: меню не должно
перехватывать текстовый курсор.

## Выполнение команды

Перед вызовом `onItemClick` меню закрывается, а trigger и query очищаются.
Стандартная команда создания типа использует семантику
`insertOrUpdateBlockForSlashMenu`.

### Текущий блок пуст или содержит только `/`

- Текущий блок обновляется до выбранного типа вместо вставки соседа.
- Его ID сохраняется.
- Trigger `/` удаляется.
- Выбранные type и props применяются к этому же блоку.
- Курсор возвращается в обновлённый блок.

### В текущем блоке есть другое содержимое

- Новый блок вставляется непосредственно после текущего.
- Исходный блок не изменяется.
- Новый блок получает уникальный ID.
- Курсор переводится в новый блок.

Этот сценарий возможен, например, при программном открытии меню в непустом
блоке или при custom-команде. Обычная кнопка `+` предварительно создаёт пустой
paragraph, поэтому выбранная команда затем преобразует именно его.

### Блок без редактируемого content

Если выбранный тип не имеет редактируемого content, редактор переводит курсор
в следующий редактируемый блок. При его отсутствии в конец документа
добавляется пустой `paragraph`. Для file/media-команд после вставки открывается
соответствующая панель файла.

Один выбор пункта должен составлять одну смысловую операцию undo/redo. При
отмене восстанавливаются исходные блоки, content, ID и позиция структуры.
Обычный `onUpdate` после операции сохраняет документ в `localStorage`.

## Закрытие без выбора

При закрытии меню без выбора:

- ни один callback пункта не выполняется;
- при сценарии с клавиатурным `/` введённый символ и query остаются обычным
  content, если пользователь явно их не удалил;
- при сценарии `+` символ `/` отсутствует;
- вставленный кнопкой `+` пустой paragraph не удаляется автоматически;
- временные decorations, ARIA-связи и состояние активного пункта очищаются.

## Кастомизация

Стандартный Slash Menu можно отключить через `slashMenu={false}` и заменить
`SuggestionMenuController` со следующими параметрами:

- `triggerCharacter` — trigger;
- `getItems(query)` — асинхронный поставщик и фильтр;
- `shouldOpen(transaction)` — проверка допустимости открытия;
- `minQueryLength` — минимальная длина query;
- `suggestionMenuComponent` — собственное React-представление;
- `onItemClick` — общий обработчик выбора;
- `floatingUIOptions` и `portalElement` — позиционирование.

`getDefaultReactSlashMenuItems(editor)` возвращает стандартные пункты с
иконками. `filterSuggestionItems(items, query)` воспроизводит стандартный поиск.
Добавление, удаление и перестановка пунктов выполняются обычными операциями над
массивом.

Программное открытие выполняется через `editor.openSuggestionMenu("/")` либо
соответствующее расширение. Реализация кнопки `+` должна переиспользовать этот
механизм, а не поддерживать отдельный несовместимый список команд.

## Граница ответственности

Эта спецификация определяет:

- открытие Slash Menu через `+` и `/`;
- вставку промежуточного paragraph;
- модель, порядок, группировку и фильтрацию пунктов;
- навигацию, выбор и закрытие;
- преобразование пустого блока и вставку после непустого;
- базовый контракт кастомизации и доступности.

Она не определяет:

- внутреннее поведение каждого типа блока после создания;
- импорт файлов и содержимое File Panel;
- Emoji Picker с триггером `:`;
- Drag Handle Menu;
- внешний вид компонентов конкретной UI-библиотеки.

## Критерии приёмки

1. Hover над редактируемым блоком показывает доступную кнопку `+`.
2. Нажатие `+` у пустого блока не создаёт новый блок и открывает Slash Menu в
   существующем блоке.
3. Нажатие `+` у непустого блока вставляет после него пустой paragraph с новым
   ID и открывает меню в нём.
4. Закрытие меню после `+` оставляет созданный paragraph в документе.
5. Ввод `/` открывает меню, а последующий текст становится query.
6. Slash Menu не открывается в code и стандартном `tableContent`.
7. Поиск без учёта регистра проверяет title и aliases.
8. Меню содержит только команды типов, поддерживаемых schema.
9. В текущей схеме доступны paragraph, heading 1–6, quote и три типа списка;
   toggle-типы отсутствуют.
10. Порядок пунктов: paragraph, heading 1–6, quote, numbered list, bullet list,
    checklist; группы соответствуют массиву без скрытой сортировки.
11. Устаревший асинхронный ответ не заменяет результаты актуального query.
12. `ArrowUp` и `ArrowDown` циклически меняют выбор, `PageUp` и `PageDown`
    переходят к границам списка.
13. `Enter` и click выполняют ровно один выбранный callback; Enter во время IME
    composition его не выполняет.
14. При выборе команды в пустом или содержащем только `/` блоке сохраняется ID
    и меняется тип этого блока.
15. При выполнении команды в непустом блоке новый блок вставляется после него,
    а исходный не изменяется.
16. Trigger и query удаляются перед выполнением выбранной команды.
17. Закрытие без выбора сохраняет введённые `/` и query как текст.
18. Результат выбора отменяется и повторяется одной операцией undo/redo.
19. Изменение сохраняется в `localStorage` общим persistence-механизмом.
20. Contenteditable и пункты меню имеют корректные ARIA-связи, а focus во время
    навигации остаётся в редакторе.

## Требуемые тесты реализации

- `+` у пустого и непустого корневого блока;
- `+` у вложенного блока;
- закрытие меню без выбора в обоих сценариях;
- `/` в начале, середине и конце непустого текста;
- запрет открытия в code и table content;
- фильтрация по title, русским и английским aliases, разному регистру;
- пустой результат и серия невалидных query;
- задержанный асинхронный ответ в неправильном порядке;
- клавиатурный цикл, PageUp/PageDown, Enter, Escape и IME composition;
- выбор каждого типа, поддерживаемого текущей schema;
- отсутствие toggle-типов;
- сохранение ID при преобразовании и новый ID при вставке;
- блок без editable content и создание trailing paragraph;
- один шаг undo/redo;
- восстановление результата из `localStorage` после перезагрузки;
- локализованные accessible names и ARIA active descendant.
