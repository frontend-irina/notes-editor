# Идентификатор блока

## Блочная модель документа

Редактор должен использовать блочную структуру документа.

Блок — минимальная структурная единица документа. Абзац, заголовок, список, изображение, таблица и другие элементы верхнего уровня представляются отдельными блоками.

Каждый блок должен содержать:

- `id` — уникальный идентификатор блока в формате UUID v7;
- `type` — тип блока;
- `props` — свойства блока;
- `content` — содержимое блока;
- `children` — дочерние блоки.

```ts
interface Block {
  id: string; // UUID v7
  type: string;
  props: Record<string, unknown>;
  content: unknown;
  children: Block[];
}
```

## Требования к идентификатору

- UUID v7 создаётся при создании нового блока.
- Идентификатор уникален в пределах всей системы, а не только одного документа.
- После создания блока его `id` не изменяется при редактировании, перемещении или изменении типа.
- Копирование блока создаёт новый UUID v7 для копии.
- Вставка внешнего содержимого создаёт новые UUID v7.
- Загрузка существующего документа сохраняет имеющиеся идентификаторы.
- Если импортируемый блок не имеет `id`, редактор генерирует UUID v7.
- Если при импорте обнаружены повторяющиеся `id`, система должна устранить конфликт генерацией новых идентификаторов.

## Назначение UUID v7

Идентификатор используется для:

- адресации блока через API;
- обновления, удаления и перемещения блока;
- сохранения ссылок на блок;
- синхронизации и совместного редактирования;
- сопоставления блоков между состояниями документа;
- хранения комментариев и другой метаинформации, связанной с блоком.

## Критерии приёмки

1. Каждый созданный блок получает корректный UUID v7.
2. В документе не существует двух блоков с одинаковым `id`.
3. Перемещение, редактирование и смена типа блока не изменяют его `id`.
4. Дублирование блока создаёт независимый блок с новым `id`.
5. После сохранения и повторной загрузки документа идентификаторы блоков сохраняются.
6. Идентификатор доступен в JSON-представлении документа и через публичный API редактора.
