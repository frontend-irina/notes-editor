# Блок Heading

## Назначение

`Heading` — текстовый блочный заголовок документа. Он задаёт семантический уровень
заголовка и содержит форматируемое inline-содержимое.

Реализация надстройки над Tiptap должна повторять публичную модель и наблюдаемое
поведение стандартного блока `heading` BlockNote.

Основной источник: [BlockNote — Typography / Heading](https://www.blocknotejs.org/docs/features/blocks/typography#heading).

Связанные спецификации:

- [Markdown для Heading](./markdown.md);
- [HTML для Heading](./html.md);
- [Paragraph](../paragraph/paragraph.md);
- [Inline Content](../../inline-content.md);
- [Идентификатор блока](../../block-id.md);
- [Formatting Toolbar](../../toolbar.md).

## Модель данных

```ts
type HeadingLevel = 1 | 2 | 3 | 4 | 5 | 6;

type HeadingBlock = {
  id: string;
  type: "heading";
  props: DefaultProps & {
    level: HeadingLevel;
  };
  content: InlineContent[];
  children: Block[];
};
```

Требования к `id` определены в [block-id.md](../../block-id.md). Формат текста,
ссылок и inline-стилей определён в [inline-content.md](../../inline-content.md).

## Конфигурация схемы

```ts
type HeadingBlockOptions = Partial<{
  defaultLevel: HeadingLevel;
  levels: HeadingLevel[];
}>;
```

| Опция | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `defaultLevel` | `1` | Уровень заголовка, создаваемого без явно заданного `level`. |
| `levels` | `[1, 2, 3, 4, 5, 6]` | Уровни, разрешённые активной схемой редактора. |

- Команды, slash menu, block type menu, input rules и shortcuts должны предлагать
  только уровни из `levels`.
- `defaultLevel` должен использоваться при вставке или нормализации heading без
  явно заданного уровня.
- Изменение конфигурации не должно молча преобразовывать уже загруженный документ
  в семантически другой тип. Неподдерживаемый уровень должен обрабатываться общей
  политикой валидации и миграции схемы.

## Поля блока

### `type`

- Всегда имеет значение `"heading"`.

### `props.level`

- Принимает значения от `1` до `6` в стандартной схеме.
- Значение по умолчанию — `1`.
- `1` представляет заголовок верхнего уровня, `2` — следующий уровень раздела,
  `3`–`6` — последовательно более глубокие подзаголовки.
- Уровень определяет семантический HTML-элемент `<h1>`–`<h6>`, а не только
  визуальный размер текста.
- Изменение `level` не изменяет `id`, `content`, совместимые стандартные props или
  `children` блока.

### Стандартные props

Heading использует те же `DefaultProps`, что и paragraph:

| Свойство | Тип | Значение по умолчанию | Поведение |
| --- | --- | --- | --- |
| `backgroundColor` | `string` | `"default"` | Цвет фона блока; наследуется вложенными блоками. |
| `textColor` | `string` | `"default"` | Цвет текста блока; наследуется вложенными блоками. |
| `textAlignment` | `"left" \| "center" \| "right" \| "justify"` | `"left"` | Выравнивание содержимого heading. |

Цвета уровня блока не должны смешиваться с `textColor` и `backgroundColor` отдельных
фрагментов `InlineContent`.

### `content`

- Содержит массив `InlineContent`.
- Пустой heading представлен как `content: []`.
- Поддерживает текст, ссылки и все стандартные inline-стили.
- `level` является prop блока и не входит в inline content.

### `children`

- Содержит дочерние блоки heading.
- Inline-содержимое дочерних блоков не входит в `content` заголовка.
- Перемещение и изменение вложенности не меняют `id` heading или его детей.

## Создание и преобразование

- Создание heading без `level` использует `defaultLevel`.
- Ввод от одного до шести символов `#`, за которыми следует пробел, в начале
  пустого текстового блока преобразует его в соответствующий разрешённый heading:
  `# ` → level 1, `## ` → level 2, …, `###### ` → level 6.
- Input rule регистрируется только для уровней из `levels`.
- `Mod+Alt+1` … `Mod+Alt+6` преобразуют текущий блок с inline content в heading
  соответствующего разрешённого уровня. `Mod` означает `Cmd` на macOS и `Ctrl`
  на Windows/Linux.
- Преобразование paragraph или другого совместимого текстового блока в heading
  сохраняет `id`, inline content, inline-стили, `children` и совместимые
  `DefaultProps`.
- Преобразование heading в другой уровень изменяет только `level`, если остальные
  свойства остаются допустимыми.
- `Mod+Alt+0` преобразует heading в paragraph согласно
  [спецификации Paragraph](../paragraph/paragraph.md).
- Каждый поддерживаемый уровень heading должен быть доступен через slash menu и
  block type menu.

## Редактирование

Heading участвует в общих операциях блочного редактора:

- ввод и редактирование inline content;
- разделение блока клавишей `Enter`;
- объединение с соседним совместимым блоком клавишами удаления на границе;
- выделение, копирование, вырезание и вставка;
- drag-and-drop;
- изменение вложенности;
- преобразование через slash menu и `BlockTypeSelect`;
- undo и redo.

Разделение, объединение и преобразование должны сохранять данные согласно общим
правилам блочной модели. Новосозданный при разделении блок получает новый UUID v7;
исходный heading сохраняет свой `id`.

Formatting Toolbar должна показывать текущий тип и уровень heading, позволять
выбрать поддерживаемый уровень и применять inline-форматирование по правилам
[toolbar.md](../../toolbar.md).

- Dropdown типа блока содержит отдельные пункты «Заголовок 1» … «Заголовок 6»
  для всех уровней из активной конфигурации `levels`.
- Пункт текущего уровня имеет selected-состояние, а кнопка выбора отображает
  «Заголовок N».
- При selection из headings разных уровней кнопка отображает смешанное состояние
  «Несколько типов».
- Выбор пункта Heading выполняет ту же команду, что и соответствующий shortcut
  `Mod+Alt+N`, и возвращает focus в редактор без потери исходного selection.

## Форматы обмена

Форматные правила вынесены в отдельные документы:

- [markdown.md](./markdown.md) определяет импорт и экспорт Heading в Markdown;
- [html.md](./html.md) определяет импорт и экспорт Heading в полный BlockNote HTML
  и interoperable HTML.

Каноническим persistence-представлением Heading остаётся публичный JSON, а не
Markdown или interoperable HTML.

## Пример JSON

```json
{
  "id": "0198f123-4567-7abc-8def-0123456789ab",
  "type": "heading",
  "props": {
    "backgroundColor": "default",
    "textColor": "default",
    "textAlignment": "left",
    "level": 2
  },
  "content": [
    {
      "type": "text",
      "text": "Раздел документа",
      "styles": {}
    }
  ],
  "children": [
    {
      "id": "0198f123-4568-7abc-8def-0123456789ab",
      "type": "paragraph",
      "props": {
        "backgroundColor": "default",
        "textColor": "default",
        "textAlignment": "left"
      },
      "content": [
        {
          "type": "text",
          "text": "Содержимое раздела",
          "styles": {}
        }
      ],
      "children": []
    }
  ]
}
```

## Граница ответственности

- Heading определяет семантический уровень и props блока.
- Inline-форматирование остаётся ответственностью модели `InlineContent`.
- Вложенность остаётся частью общей блочной модели.
- Heading не определяет общую стратегию outline/оглавления. Потребители могут
  строить outline по `type`, `level`, порядку и вложенности блоков.

## Критерии приёмки

1. Публичный JSON heading соответствует модели BlockNote и содержит стабильный
   UUID v7.
2. Стандартная схема поддерживает levels 1–6 и `defaultLevel: 1`.
3. Создание heading без уровня использует `defaultLevel`.
4. `# ` … `###### ` создают разрешённые уровни heading.
5. `Mod+Alt+1` … `Mod+Alt+6` преобразуют совместимые блоки только в уровни,
   присутствующие в активной схеме.
6. Изменение уровня или типа сохраняет `id`, совместимые props, inline content и
   children.
7. Inline content, ссылки и стили переживают сохранение и повторную загрузку.
8. Импорт и экспорт Markdown соответствуют [markdown.md](./markdown.md).
9. Импорт и экспорт HTML соответствуют [html.md](./html.md).
10. Read-only режим запрещает изменение документа.
11. Ошибочный или неподдерживаемый HTML не создаёт некорректный heading.
12. Formatting Toolbar содержит все разрешённые уровни Heading, корректно
    показывает текущий или mixed-уровень и меняет его с сохранением данных блока.

## Открытые вопросы для проверки по эталону

Перед объявлением полной совместимости необходимо отдельно зафиксировать
наблюдаемое поведение BlockNote для следующих случаев:

- результат `Enter` в начале, середине и конце heading каждого уровня;
- результат `Backspace` в начале heading и объединения с блоком другого типа;
- multi-block преобразование heading разных уровней через Formatting Toolbar.
