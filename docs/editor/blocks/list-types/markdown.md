# Markdown для блоков элементов списка

## Назначение

Документ определяет импорт и экспорт `bulletListItem`, `numberedListItem` и
`checkListItem` между публичной моделью и Markdown.

Общие правила формата, безопасности, diagnostics и lossy-преобразований описаны в
[общей спецификации Markdown](../../markdown.md). Модель блоков определена в
[list-types.md](./list-types.md), а inline-разметка — в
[inline-content.md](../../inline-content.md).

## Представление

| Markdown | Публичная модель |
| --- | --- |
| `- пункт`, `* пункт`, `+ пункт` | `bulletListItem` |
| `1. пункт` | `numberedListItem` |
| `- [ ] задача` | `checkListItem` с `checked: false` |
| `- [x] задача` / `- [X] задача` | `checkListItem` с `checked: true` |

## Импорт Markdown

- Маркеры `-`, `*` и `+` создают `bulletListItem`; исходный вид маркера не
  сохраняется.
- Ordered marker создаёт `numberedListItem`; начальное число группы записывается
  в `start` первого элемента.
- Task-list marker создаёт `checkListItem` и определяет `checked`.
- Маркер, номер и `[ ]` / `[x]` не входят в `InlineContent[]`.
- Отступы преобразуются в `children` ближайшего родительского list item.
- Импортированные элементы получают новые UUID v7 и default `DefaultProps`.
- Отсутствующий в активной схеме тип заменяется безопасным fallback с warning.

## Inline content

Подпись элемента использует общие Markdown mappings для `bold`, `italic`,
`strike`, `code` и `Link`. Совместимые стили комбинируются, соседние фрагменты с
одинаковыми styles нормализуются. Маркеры списка никогда не включаются в текст.

## Экспорт Markdown

```md
- Маркированный пункт
  3. Вложенный нумерованный пункт
- [ ] Невыполненная задача
- [x] Выполненная задача
```

- `bulletListItem` использует единый канонический marker.
- `numberedListItem` использует числовой marker; явный `start` первой группы
  задаёт начальное число, а продолжение может нормализоваться.
- Разрыв нумерации начинает новую группу либо создаёт warning о потере номера.
- `checkListItem` экспортируется как `[ ]` или `[x]` согласно `checked`.
- Дочерние list items получают корректный отступ под родительским marker.
- Непредставимые вложенные blocks выводятся после списка с warning.
- UUID, `DefaultProps` и неподдерживаемые inline styles не экспортируются.

## Round trip

Цикл `ListItemBlock[] → Markdown → ListItemBlock[]` сохраняет порядок, видимый
текст, поддерживаемую вложенность, типы bullet/numbered/check и `checked`.
Допустима нормализация markers, ordered delimiters, автоматически продолжающихся
номеров, отступов и пустых строк.

Не сохраняются UUID, `DefaultProps` и некоторые произвольные разрывы нумерации.

## Критерии приёмки

1. Bullet, ordered и task-list синтаксис создаёт соответствующие типы блоков.
2. Маркеры не попадают в `content`.
3. Начальный номер восстанавливается в `start`.
4. Task-list состояние восстанавливается в `checked`.
5. Вложенность через отступы восстанавливается в `children`.
6. Экспорт использует канонические и повторно импортируемые markers.
7. Непереносимые свойства отражаются в warnings.
8. Round trip сохраняет поддерживаемую семантику списка.

## Открытые вопросы для проверки по эталону

- поддержка ordered marker с `)`;
- точная политика разрывов нумерации и `start` у последующих элементов;
- число пробелов для каждого уровня вложенности;
- экспорт пустых list items и hard breaks;
- fallback для нестандартных дочерних blocks.
