# Блоки элементов списка

## Назначение

BlockNote представляет список не отдельным блоком-контейнером, а последовательностью
блоков-элементов списка. В проекте поддерживаются три типа:

- `bulletListItem` — маркированный элемент;
- `numberedListItem` — нумерованный элемент;
- `checkListItem` — элемент с флажком.

Реализация надстройки над Tiptap должна сохранять публичную модель этих блоков и
наблюдаемое поведение BlockNote.

Основной источник: [BlockNote — List Types](https://www.blocknotejs.org/docs/features/blocks/list-types).

Связанные спецификации:

- [Markdown для элементов списка](./markdown.md);
- [HTML для элементов списка](./html.md);
- [Идентификатор блока](../../block-id.md);
- [Inline Content](../../inline-content.md).

## Общая модель

Все элементы списка являются обычными блоками документа с inline-содержимым и
массивом дочерних блоков:

```ts
type ListItemBlock =
  | BulletListItemBlock
  | NumberedListItemBlock
  | CheckListItemBlock;

type BulletListItemBlock = {
  id: string;
  type: "bulletListItem";
  props: DefaultProps;
  content: InlineContent[];
  children: Block[];
};

type NumberedListItemBlock = {
  id: string;
  type: "numberedListItem";
  props: DefaultProps & {
    start?: number;
  };
  content: InlineContent[];
  children: Block[];
};

type CheckListItemBlock = {
  id: string;
  type: "checkListItem";
  props: DefaultProps & {
    checked: boolean;
  };
  content: InlineContent[];
  children: Block[];
};

```

`DefaultProps` включает стандартные свойства блока:

| Свойство | Тип | Значение по умолчанию |
| --- | --- | --- |
| `backgroundColor` | `string` | `"default"` |
| `textColor` | `string` | `"default"` |
| `textAlignment` | `"left" \| "center" \| "right" \| "justify"` | `"left"` |

Формат `id` определяется в [block-id.md](../../block-id.md), а формат текста,
ссылок и inline-стилей — в [inline-content.md](../../inline-content.md).

## Общие правила

- `content` содержит подпись элемента списка и может быть пустым массивом.
- `children` содержит структурно вложенные блоки. Вложенные элементы списка
  формируют следующий уровень списка.
- Перемещение элемента, изменение вложенности и преобразование между совместимыми
  типами не должны менять его `id`.
- Маркер, номер и checkbox являются интерфейсом блока и не входят в
  `content`.
- Соседние совместимые элементы визуально объединяются в список средствами
  представления. Дополнительный публичный блок-контейнер для этого не создаётся.
- Ввод, удаление, разделение, объединение, копирование, вставка, drag-and-drop,
  nest/unnest и undo/redo используют общие правила блочного редактора.

## Маркированный элемент

`bulletListItem` отображается с ненумерованным маркером.

- Специальных props помимо `DefaultProps` нет.
- В публичном JSON символ маркера не хранится.
- Вид маркера может зависеть от темы и уровня вложенности, но не меняет модель
  документа.

```json
{
  "id": "0198f123-4567-7abc-8def-0123456789ab",
  "type": "bulletListItem",
  "props": {
    "backgroundColor": "default",
    "textColor": "default",
    "textAlignment": "left"
  },
  "content": [{ "type": "text", "text": "Первый пункт", "styles": {} }],
  "children": []
}
```

## Нумерованный элемент

`numberedListItem` отображается с номером и дополнительно поддерживает prop
`start?: number`.

- `start` задаёт начальный номер непрерывной группы соседних нумерованных
  элементов. В стандартном представлении BlockNote значение учитывается у
  первого элемента такой группы.
- Если `start` не указан и перед элементом нет продолжаемого нумерованного списка,
  нумерация начинается с `1`.
- Если `start` не указан после предыдущего совместимого нумерованного элемента,
  отображаемое значение увеличивается относительно предыдущего элемента.
- Чтобы перезапустить нумерацию с заданного значения, элемент должен начинать
  новую непрерывную группу. `start` у элемента, непосредственно следующего за
  другим `numberedListItem` того же уровня, не разрывает группу и не заменяет
  вычисленный номер этого элемента.
- Вычисленные номера являются данными представления и не записываются обратно в
  `props.start` остальных элементов группы.
- Вычисленный номер не следует записывать в `content`.

```json
{
  "id": "0198f123-4567-7abc-8def-0123456789ab",
  "type": "numberedListItem",
  "props": {
    "backgroundColor": "default",
    "textColor": "default",
    "textAlignment": "left",
    "start": 3
  },
  "content": [{ "type": "text", "text": "Третий пункт", "styles": {} }],
  "children": []
}
```

## Элемент с флажком

`checkListItem` отображает флажок, который пользователь может переключать.

- `checked: false` означает невыполненный элемент.
- `checked: true` означает выполненный элемент.
- Переключение флажка меняет только `props.checked`; `id`, `content` и `children`
  сохраняются.
- Состояние является частью документа, сериализуется и участвует в undo/redo.
- В read-only режиме состояние отображается, но не изменяется.

```json
{
  "id": "0198f123-4567-7abc-8def-0123456789ab",
  "type": "checkListItem",
  "props": {
    "backgroundColor": "default",
    "textColor": "default",
    "textAlignment": "left",
    "checked": false
  },
  "content": [{ "type": "text", "text": "Выполнить задачу", "styles": {} }],
  "children": []
}
```

## Преобразование и редактирование

- Создание и преобразование через slash menu, меню типа блока и публичный API
  должны приводить к одному и тому же публичному JSON.
- При преобразовании совместимого inline-блока сохраняются `id`, `content`,
  `children` и совместимые `DefaultProps`.
- При преобразовании в `checkListItem` отсутствующий `checked` получает значение
  `false`.
- При преобразовании из `checkListItem` prop `checked` удаляется, если целевой тип
  его не поддерживает.
- При преобразовании из `numberedListItem` prop `start` удаляется, если целевой тип
  его не поддерживает.
- Изменение вложенности влияет на визуальную группировку и нумерацию, но не должно
  менять inline-содержимое элемента.

## Горячие клавиши

| Тип блока | Сочетание |
| --- | --- |
| `numberedListItem` | `Mod+Shift+7` |
| `bulletListItem` | `Mod+Shift+8` |
| `checkListItem` | `Mod+Shift+9` |

`Mod` означает `Cmd` на macOS и `Ctrl` на Windows/Linux.

- Shortcut преобразует текущий блок только тогда, когда его schema content имеет
  тип `inline`.
- Для несовместимого блока команда возвращает `false` и не меняет документ.
- Преобразование использует те же правила сохранения `id`, `content`, `children`
  и совместимых props, что и меню типа блока.
- В read-only режиме shortcut не должен изменять документ.

## Input rules

Input rules применяются в начале редактируемого блока после ввода маркера и
завершающего пробела:

| Ввод | Результат |
| --- | --- |
| `- `, `+ ` или `* ` | `bulletListItem` |
| `<число>. ` | `numberedListItem` с `start`, если число не равно `1` |
| `[ ] `, включая пробелы внутри скобок | `checkListItem` с `checked: false` |
| `[x] ` или `[X] ` | `checkListItem` с `checked: true` |

- Перед маркером допускается не более одного пробельного символа.
- Служебный marker и завершающий пробел удаляются из `content`.
- Bullet и numbered rules не преобразуют блок `heading`.
- Numbered rule поддерживает точку после числа; форма `<число>) ` стандартной
  input rule BlockNote не распознаётся.
- Срабатывание правила является одной операцией undo.

## Поведение Enter

Специальный обработчик `Enter` применяется, когда selection свёрнут и курсор
находится внутри одного из трёх list-item blocks.

- В пустом элементе `Enter` преобразует текущий блок в `paragraph`, сбрасывая
  специфичные для списка props.
- В непустом элементе `Enter` разделяет блок в позиции курсора.
- Часть content до курсора остаётся в исходном элементе; часть после курсора
  переносится в новый соседний элемент того же типа.
- Новый элемент получает собственный ID и default props своего типа; props
  исходного элемента специально не копируются.
- Если selection не свёрнут или курсор находится не в ожидаемом типе блока,
  специальный обработчик возвращает `false`, а событие передаётся общей цепочке
  команд редактора.
- Пограничное поведение `Backspace` и `Delete` остаётся частью общих правил
  блочного редактора и требует отдельной спецификации.

## Форматы обмена

Форматные правила вынесены в отдельные документы:

- [markdown.md](./markdown.md) определяет импорт и экспорт элементов списка в
  Markdown;
- [html.md](./html.md) определяет импорт и экспорт элементов списка в полный
  BlockNote HTML и interoperable HTML.

Каноническим persistence-представлением элементов списка остаётся публичный JSON.

## Критерии приёмки

1. Все три поддерживаемых типа сериализуются с точными значениями `type`.
2. Каждый элемент содержит `id`, `props`, `content` и `children`.
3. Маркеры и вычисленные номера не попадают в `content`.
4. `numberedListItem.start` задаёт начало новой непрерывной группы, а последующие
   соседние элементы получают вычисленные последовательные номера.
5. Переключение `checkListItem` сохраняет `checked` в документе и поддерживает
   undo/redo.
6. Вложение и извлечение блока сохраняют его `id`, props и inline-содержимое.
7. Импорт и экспорт Markdown соответствуют [markdown.md](./markdown.md).
8. Импорт и экспорт HTML соответствуют [html.md](./html.md).
9. Горячие клавиши `Mod+Shift+7`–`Mod+Shift+9` преобразуют совместимый inline-
    блок в соответствующий тип элемента списка.
10. Input rules создают bullet, numbered и check list items и удаляют введённый
    служебный marker из content.
11. `Enter` в пустом list item преобразует его в Paragraph, а в непустом разделяет
    его с сохранением типа нового элемента.
