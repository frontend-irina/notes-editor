# OpenSpec

OpenSpec используется для подготовки и сопровождения изменений: предложение,
спецификации изменения, техническое решение и список задач, затем реализация
и архивирование.

## Установка

Требуется Node.js 20.19.0 или новее. В проекте настроен OpenSpec CLI 1.12.0:

```bash
npm install -g @fission-ai/openspec@1.12.0
openspec --version
```

Конфигурация и навыки уже находятся в репозитории. При первом подключении
другого AI-инструмента выполните `openspec init` и выберите нужную интеграцию.
Для обновления сгенерированных навыков после обновления CLI: `openspec update`.

## Структура

- `openspec/config.yaml` — схема `spec-driven`, язык, контекст и правила проекта.
- `openspec/changes/` — активные изменения; `archive/` внутри него — завершённые.
- `openspec/specs/` — требования, накопленные после синхронизации изменений.
- `.agents/skills/openspec-*/` — сгенерированные навыки для Codex.

Начальная структура каталогов сохраняется в Git с помощью `.gitkeep`;
спецификации и изменения появятся при работе над первой задачей.
Конфигурацию и сгенерированные навыки следует хранить в Git.

## Работа с изменением

В чате Codex используйте навыки по имени:

1. `$openspec-explore` — исследовать задачу и ограничения, если нужно.
2. `$openspec-propose` и описание задачи — подготовить предложение и артефакты.
3. Проверить предложение, требования и задачи.
4. `$openspec-apply-change` — реализовать задачи выбранного изменения.
5. Выполнить `npm run lint`, `npm run build` и проверки затронутого поведения.
6. `$openspec-archive-change` — синхронизировать спецификации и архивировать
   завершённое изменение.

Для уточнения активного изменения доступен `$openspec-update-change`, для
отдельной синхронизации требований — `$openspec-sync-specs`.

В терминале:

```bash
openspec list
openspec list --specs
openspec validate --all --strict
```

Сразу после настройки изменений ещё нет, поэтому валидировать нечего.
Если новые навыки не появились в текущей сессии, откройте новую задачу Codex
в этом проекте.

## Связь с существующей документацией

[`docs/agent.md`](../agent.md) остаётся центральным индексом, а `docs/editor/`
— источником существующих требований. OpenSpec описывает предлагаемые изменения
и ссылается на эти документы. Не переносите все спецификации автоматически
и не создавайте расходящиеся копии требований.

Если изменение меняет установленное поведение, явно отразите это в предложении
и обновите соответствующие документы в `docs/` до архивирования. При добавлении,
перемещении или удалении документа обновляйте индекс `docs/agent.md`.
