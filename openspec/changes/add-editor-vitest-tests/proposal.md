## Why

После декомпозиции редактор состоит из небольших модулей, но рядом с ними нет регулярных тестов. Существующий сравнительный Node-стенд привязан к Git baseline и не предоставляет удобного независимого запуска тестов каждого модуля; Vitest обеспечит повторяемую проверку логики и компонентов без доступа к desktop browser automation.

## What Changes

- Добавить Vitest, окружение jsdom, React Testing Library и отчёт покрытия как dev-инструменты, npm-команды разового запуска, watch и coverage.
- Создать соседние `.test.ts`/`.test.tsx` для каждого модуля с исполняемой логикой в `src/editors`, включая обе оболочки редакторов; дополнительно покрыть `src/app/EditorHistoryActions.tsx`.
- Проверять типовые контракты TypeScript, реэкспорты — через потребителей; CSS и файлы только с типами не получают искусственных runtime-тестов. `tiptap/types.ts` получает runtime-тест defaults, поскольку содержит значения.
- Ввести небольшие общие fixtures и helpers для настоящих ProseMirror transactions, React lifecycle и контролируемых DOM API.
- Перенести применимые сценарии старого сравнительного стенда в тесты с самостоятельными ожидаемыми результатами, без чтения Git и подмены исходного кода.
- Документировать матрицу «модуль → тест → сценарии», правила изоляции и ограничения jsdom.
- По согласованию пользователя исправить два выявленных отклонения от действующих требований: сравнение inline-стилей независимо от порядка marks и приоритет специализированных HTML-правил списков перед generic listItem из StarterKit.
- После дополнительного согласования исправить перенос Slice между независимыми совместимыми schema, актуальность history при замене editor и доступность меню типа блока/цвета через стандартный Portal.

## Capabilities

### New Capabilities

Новых требований продукта нет: тестовая инфраструктура и согласованные исправления соответствия существующим требованиям; `skip_specs: true`.

### Modified Capabilities

Нет. Тесты опираются на [архитектуру](../../../docs/architecture/project.md), [ID](../../../docs/editor/block-id.md), [inline content](../../../docs/editor/inline-content.md), [menu](../../../docs/editor/menu.md), [toolbar](../../../docs/editor/toolbar.md), [drag-and-drop](../../../docs/editor/drag-and-drop.md) и документы блоков в [индексе](../../../docs/agent.md). Требования HTML проверяются в пределах существующих schema/marks, а не отсутствующих общих API импорта/экспорта. Новые функции редактора и изменение публичного JSON не планируются.

## Impact

`package.json`, `package-lock.json`, отдельный `vitest.config.ts`, настройка типизации тестов, `.gitignore` для coverage, соседние тесты в `src/editors` и `src/app`, helpers в `src/test`, `docs/architecture/testing.md`, `docs/architecture/project.md`, `docs/agent.md`, README с командами. Runtime-зависимости сохраняются. Runtime-изменения ограничены перечисленными согласованными исправлениями соответствия существующим требованиям.

Изменение строится на текущей структуре `refactor-editor-modules`, но не закрывает его незавершённые браузерные задачи 5.3/8.1 и не изменяет исторический сравнительный стенд. Если новый тест обнаружит расхождение кода с действующей спецификацией, оно фиксируется отдельно и согласуется до изменения поведения; тест не закрепляет ошибку как требование.
