## Context

Мотивация описана в [proposal.md](proposal.md). Пользователь выбрал развитие функциональных папок внутри `src/editors/tiptap`, без выделения независимого ядра и React-адаптера.

Исследование исходников выявило 11 TS/TSX/CSS-файлов длиннее 100 физических строк, включая пустые; 6 из них длиннее 150. `BlockMenu.ts` содержит 295 строк, `DragAndDrop.ts` — 268, `extensions.ts` — 250, `App.css` — 212, `serialization.ts` — 203, `Heading.ts` — 191. Типы, хранение и сериализация уже отделены от `TiptapEditor`; описание монолита в архитектурной документации устарело. Автоматическая тестовая инфраструктура отсутствует, доступны lint, build и браузерные проверки.

## Goals / Non-Goals

**Goals:**

- Находить код сначала по возможности редактора, затем по роли внутри неё.
- Сохранить одного владельца каждого состояния и направленные зависимости без циклов.
- Отделить преобразования документа от React, DOM и localStorage.
- Удалить фактические дубликаты общих блочных операций, сохранив различия поведения блоков.
- Привести затронутые крупные модули к ориентиру 100–150 строк при обычном читаемом форматировании.

**Non-Goals:**

- Изменение поведения, исправление ранее существовавших функциональных расхождений, расширение публичного API.
- Перемещение всего проекта в глобальные `components`, `hooks`, `services` или введение общей папки `utils`.
- Дробление всех файлов свыше 100 строк и внедрение жёсткого lint-лимита; связный `types.ts` на 110 строк остаётся целиком.
- Добавление runtime-зависимостей или общей тестовой платформы в рамках декомпозиции.

### 2. Общие операции и обработчики блоков

`block-position.ts` предоставляет поиск глубины ближайшего `blockContainer` по `ResolvedPos`; его используют paragraph, heading, списки и общее клавиатурное поведение. Поиск блока по ID можно разместить здесь для меню и drag-and-drop, сохранив семантику обхода и адаптируя локальные результаты к потребителям.

`unnest-block.ts` содержит одну реализацию `liftToOuterGroup` и проверки диапазона, общие для пустых paragraph и heading. Операция работает с переданной транзакцией и возвращает признак применимости; dispatch остаётся у вызывающего обработчика.

`paragraph-enter.ts`, `heading-enter.ts`, `quote-enter.ts` содержат отдельные обработчики с явно переданным редактором и необходимым типом узла. Нельзя объединять их универсальным split с набором флагов: они различаются выбором следующего типа, props, допустимым selection и переносом children. `BlockBehavior` сохраняет текущий приоритет 1000 и подключает обработчик цитаты, даже если его реализация находится в `blocks/quote`; перенос функции не меняет порядок обработки shortcuts. Общая команда удаления пустого блока находится в `delete-empty-block.ts`.

### 3. Конфигурация и сериализация

`editor-extensions.ts` предоставляет фабрику конфигурации, использующую те же настройки StarterKit, порядок, имена и приоритеты extensions. `TiptapEditor` отвечает за React lifecycle, загрузку, сохранение и подключение UI. Старый `extensions.ts` удаляется после обновления импортов; постоянная прослойка совместимости для внутренних импортов не нужна.

`serialization/inline.ts` содержит обе стороны inline-преобразования и внутреннюю функцию преобразования marks. `serialization/blocks.ts` содержит обе стороны рекурсивного преобразования блоков и использует inline-модуль. `serialization/index.ts` экспортирует только существующие блочные точки входа для storage. Старый `serialization.ts` удаляется: одновременно файл и одноимённую папку оставлять нельзя из-за неоднозначности разрешения импорта.

Сохраняются текущие fallback, нормализация текста/ссылок, props, children, генерация ID и формат хранения. Эти модули не зависят от React, DOM или storage.

### 4. Меню

`menu-state.ts` владеет `PluginKey`, закрытым состоянием, типом metadata и функцией применения транзакции. Сохраняются mapping якорей с association -1, условия закрытия и сброс индекса при изменении запроса.

`menu-commands.ts` содержит открытие для блока, закрытие и выполнение пункта. `menu-input.ts` содержит ввод `/`, клавиатурную навигацию, Enter с проверкой composition и обработчики закрытия. `menu-decorations.ts` создаёт кнопку добавления и decorations, используя команды. `menu-accessibility.ts` обновляет и очищает ARIA-атрибуты. `BlockMenu.ts` собирает плагин; `BlockMenuView.tsx` импортирует ключ и команды из соответствующих модулей, не из extension.

Состояние не импортирует команды или UI. Команды импортируют состояние; обработчики и decorations импортируют команды; сборка находится над ними. Альтернатива с экспортами из `BlockMenu.ts` создаёт обратные зависимости после извлечения частей.

### 5. Перетаскивание

`block-range.ts` вычисляет диапазон блока и расширение до выделенных блоков. `drag-transfer.ts` создаёт preview и HTML/text-представления. `drag-session.ts` инкапсулирует изменяемую активную сессию, начало и очистку preview; предоставляет операции чтения, начала и завершения вместо экспортированной изменяемой переменной. Общие типы диапазона, сессии и состояния курсора находятся в `types.ts`.

Сессия остаётся общей между экземплярами редактора: перевод в локальное состояние плагина нарушил бы существующий межредакторный перенос. Состояние drop cursor остаётся локальным для плагина. Завершение сессии освобождает preview, а обработчик отдельно сбрасывает курсор соответствующего view, сохраняя текущую последовательность действий.

`drop-handler.ts` определяет drop position и выполняет транзакции переноса внутри редактора или между редакторами. `move-selection.ts` содержит клавиатурное перемещение. `drag-decorations.ts` строит handle и курсор; получает позицию курсора аргументом, чтобы не импортировать extension. `DragAndDrop.ts` хранит ключ плагина, локальный reducer курсора и связывает события с операциями. Сессия и операции не импортируют `DragAndDrop.ts`, что исключает цикл.

### 6. React и CSS

`EditorHistoryActions` получает `Editor | null`, подписывается на доступность undo/redo и отображает кнопки. `App` сохраняет редакторы смонтированными при переключении вкладок, как сейчас. Тема извлекается без изменения значений.

`use-block-type-select.ts` владеет anchor, сохранённым selection и обработчиками выбора; `BlockTypeSelect` остаётся представлением меню. Группы inline-оформления, выравнивания и ссылки получают явно необходимые props. `TiptapToolbar` сохраняет общую подписку на состояние для кнопок; `LinkButton` инкапсулирует текущий prompt и команду ссылки. Не добавлять повторные подписки без необходимости.

`App.css` содержит оболочку и вкладки; `blocknote-editor.css` — `.bn-*`; `editor.css` — оболочку Tiptap, блоки, отступы, заголовки и цитаты; стили списков и drag-and-drop находятся в их папках. Существующие `menu.css` и `toolbar.css` сохраняются. Каждый CSS подключается в одной точке владельцем или композицией редактора. Общая CSS-переменная высоты первой строки остаётся в `editor.css`, поскольку используется боковыми кнопками. Media queries распределяются вместе с соответствующими правилами. Сохраняются каскад, специфичность и внешний вид на ширинах выше и ниже 600px.

### 7. Интерфейсы и размер

Внутренние импорты используют конкретные файлы; `index.ts` применяется на границах функциональных папок и не добавляется автоматически в каждый каталог. UI не становится зависимостью schema, сериализации или блочных операций. `types.ts` и `uuid.ts` остаются общими нижними зависимостями.

100–150 строк — ориентир для законченной обязанности, включая импорты и пустые строки. Целью является разбиение перечисленных крупных файлов, а не сжатие форматирования. Если цельный модуль после извлечения превышает 150 строк, перед завершением нужно объяснить его связность и рассмотреть дополнительную смысловую границу; обоснование заносится в архитектурный документ.

## Risks / Trade-offs

- Изменение транзакций при удалении дублей → переносить операции без изменения алгоритма, проверить selection, children, marks, ID и undo/redo до и после.
- Нарушение обработки Enter из-за нового места подключения → сохранить регистрацию и приоритет `BlockBehavior`, извлекать только тело обработчика цитаты.
- Утечка preview или потеря межредакторного переноса → проверить начало, drop, Escape, dragend и уничтожение редактора; оставить общую сессию.
- Изменение каскада CSS → сравнить вкладки, toolbar, боковые кнопки, списки и мобильные отступы до/после.
- Больше файлов и импортов → ограничить внешние экспорты и сохранить расположение по возможностям.
- Спецификации описывают больше возможностей, чем реализовано → зафиксировать исходные ограничения при проверке и отличать регрессии от старых расхождений, не расширять рефакторинг исправлениями.

## Migration Plan

По прямому указанию пользователя браузерная проверка отделена от реализации и не блокирует перенос кода. Проверки транзакций выполняются сравнительным Node-стендом; работа в настоящем браузере, визуальная проверка и нативные события остаются отдельными незавершёнными задачами. Проверка адаптера storage со стабом localStorage не считается проверкой браузерного хранилища.

1. Зафиксировать исходные lint/build и браузерные сценарии для последующего сравнения.
2. Выделить общие операции, обработчики блоков, schema, marks и конфигурацию.
3. Разделить сериализацию, затем меню и drag-and-drop, обновляя импорты при каждом переносе.
4. Разделить UI и CSS, актуализировать `docs/architecture/project.md` по итоговой структуре.
5. Проверить размеры, направление зависимостей, lint/build и перечисленные регрессионные сценарии. Сохранить результаты проверок в change.

Миграция localStorage не требуется. Откат выполняется обратным применением изменений исходников и импортов, без очистки пользовательских документов.
